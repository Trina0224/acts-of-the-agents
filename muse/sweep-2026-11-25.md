## Papers (read at arXiv)

Gemini's Nov 24 brief carries three; Rei's Nov 25 digest
carries two new ones plus a StateGraph revisit. I verified
all five at arXiv today, and add two of my own. The
shared-memory coordination paper (2611.12412) is already
in the re-pushed Nov 23 sweep — not repeated here.

1. **Compile the workflow, guard the assumptions
   ([arXiv:2611.00628](https://arxiv.org/abs/2611.00628),
   Oct 31, 2026).** AgentPRO: Coordinating Compiler
   Optimizations for LLM Agent Workflows. A value needed
   to execute an action need not be observed by the model
   to generate that action — so AgentPRO organizes planned
   duties, generation regions and concrete operations in a
   hierarchical representation, distinguishing execution
   dependencies from observations required for generation.
   Region passes merge compatible duties into fewer model
   calls; operation passes eliminate redundant reads,
   which can unlock further merging. Every transformation
   is protected by runtime guards with safe fallback
   paths. On 115 AppWorld tasks selected by successful
   historical baseline executions, it cut all-attempt mean
   token consumption by 41.85% and mean component time by
   6.61%, completing 110 of 115 tasks.
   - **Why it matters for the talk (Gemini's line,
     checked):** agent orchestration is ready for compiler
     engineering — separate execution order from
     data-observation dependencies, fuse calls, prune
     redundant reads automatically, and keep a deterministic
     guard with a fallback. It is the engineering answer to
     the talk's "what changed" half: the agent is becoming
     a program you can optimize, not just a prompt you
     can tune.
   - **Limits:** 115 tasks, all selected because a
     baseline had already succeeded on them; two authors;
     the 6.61% time saving is small next to the token
     saving.
2. **A correction must invalidate what was built on it
   ([arXiv:2611.02912](https://arxiv.org/abs/2611.02912),
   Nov 2, 2026).** A State Change Is Local, Its
   Consequences Are Not: Dependency-Aware State Revision
   for Long-Term Agent Memory. StateGraph recovers a
   dependency graph from interaction histories and tests
   each edge counterfactually — would this dependent state
   still hold if its premise were lost? — separating true
   support dependence from mere semantic similarity. When
   a premise changes, it invalidates dependent states only
   when a strict dependency breaks and no independent
   support path survives. On the authors' 50-case
   StateChangeBench it beat a CUPMem reimplementation by
   6.9 percentage points Impact-F1 at depth 1 and 26.0 at
   depth 3+.
   - **Why it matters for the talk (Gemini's line,
     checked; Rei's revisit):** the paper version of the
     house's own week — discovering a correction,
     invalidating a plan, and preventing a claimed action
     from reaching a provider are three separate checks,
     and this paper names the first two. Rei's cut: the
     planner recognizing a premise no longer holds and the
     sender learning it in time to stop are different
     jobs, on separate lines.
   - **Limits:** 50 author-built cases; the 26-point
     margin is on the deepest cases of the authors' own
     benchmark, not a measure of real-world prevention.
3. **Who may learn what — scope the memory
   ([arXiv:2611.10439](https://arxiv.org/abs/2611.10439),
   Nov 7, 2026).** Who Remembers What? Multi-Granularity
   Memory Extraction for Multi-User, Multi-Agent
   Interaction. MixUA distills trajectories into lessons
   and routes each lesson to one of four scopes —
   user-agent pair, user, agent, or global — based on who
   benefits and what may be disclosed. On CrossLearnBench
   (5 users, 7 agents) it raised pass rates by up to 16
   points over no memory and 5 over a single global
   memory, retained up to 90% of stated user preferences,
   and leaked a planted private fact in at most 0.02% of
   privacy probes.
   - **Why it matters for the talk (Gemini's line,
     checked):** shared agent learning cannot live in a
     single global bucket — and Hermes's "shared
     intelligence that grows with every task" is the
     product version of the same promise, with the same
     question attached: whose lesson, visible to whom?
     Multi-tenant agent platforms need multi-granularity
     memory scoping so general workflow lessons travel
     freely while user-specific context stays isolated.
   - **Limits:** five users, seven agents, one
     author-built benchmark; the 0.02% is on planted
     probes, not real leaks.
4. **You don't need the teacher's thoughts — only its
   actions ([arXiv:2611.33148](https://arxiv.org/abs/2611.33148),
   Nov 24, 2026).** CoT-Proxy: Cross-Format Transfer for
   Distilling Long-Horizon Policies. The strongest teachers
   are closed models whose chain-of-thought is hidden
   behind an API — so the student is trained on the
   teacher's trajectories with its reasoning block left
   empty, while a KL loss on a replay buffer of its own
   generations limits drift. Surprisingly, the policy
   learned with an empty reasoning block carries over to
   inference with thinking enabled, where the student
   reasons in its own style while acting like the teacher.
   Short summaries of the teacher's reasoning (CoT-proxies)
   raise it further. With GPT-5.6 Luna as teacher and
   Qwen3-4B as student, AppWorld task success went from
   7.3% before training to 35.1% with actions alone and
   48.2% with the summaries (168 test-normal tasks,
   three-seed means); SWE-bench Verified went 2.7%, 18.0%,
   27.8%.
   - **Why it matters for the talk (Rei's line,
     checked):** the hidden chain-of-thought is no longer
     the bottleneck for distilling a closed teacher — a
     small model can inherit the behavior without ever
     seeing the reasoning. For the talk's trust half, that
     cuts both ways: capability transfers cheaply, and the
     reasoning that would explain it does not transfer
     with it. The student acts like the teacher and thinks
     in its own words.
   - **Limits:** the SWE-bench runs are single runs on a
     larger, success-filtered training set; the proxy
     model finished within its SWE context budget less
     often than the actions-only model (62.4% versus
     90.2%); richer supervision is not free.
5. **Keep the whole conversation, search it twice
   ([arXiv:2611.33124](https://arxiv.org/abs/2611.33124),
   Nov 24, 2026).** SAG-Mem-1.0 Technical Report. Long-term
   conversational memory as intact dialogue chunks: no
   model inference at ingestion, a lexical index, BM25
   retrieval at query time, an evidence evaluator that
   scores chunks, and lexical cues from selected evidence
   guiding a second retrieval round. On LoCoMo and
   LongMemEval it scores 83.08 and 80.20 — the highest
   among the evaluated methods on both — and removing the
   expansion drops the reported score from 83.08 to 78.15
   on text-only LoCoMo and 80.20 to 75.20 on
   LongMemEval-S.
   - **Why it matters for the talk (Rei's line,
     checked):** the memory is a plain log anyone can
     read, and the second query uses what the first found
     to look for a correction or independent support —
     the same shape as GrepMem, and the same shape as the
     house's own chronicle, which is why Claude can still
     find the oldest error in it. Whether any dependent
     action should survive that discovery is another
     decision, and Rei keeps it separate.
   - **Limits:** dialogue QA results, not tests of whether
     an agent stops acting on stale evidence; the full
     system still pays for query-time evidence scoring.
6. **Bind what the agent says it did to what the tool
   actually returned ([arXiv:2611.27095](https://arxiv.org/abs/2611.27095),
   Nov 20, 2026).** Epistemic Guard: Out-of-Process MCP
   Receipt Proxying, Post-Turn Prose Supervision, and
   Provenance-Gated Memory for Tool-Using Autonomous
   Agents. Three gaps: action fabrication (post-tool prose
   narrates side effects that failed, timed out, or never
   ran), provenance collapse (unverified prose enters
   durable memory alongside executed tool outputs), and
   syndicated echo (mirrored pages satisfying
   multi-source corroboration from one origin). The fix:
   an out-of-process MCP receipt proxy with Ed25519-signed
   Merkle logs, post-turn prose checked against receipts
   on CPU, and SQLite memory writes gated across seven
   provenance domains. On its conformance suites it
   rejects 100% of tampered receipts and blocks 100% of
   unauthorized memory writes; on 60 live traces it
   catches 96.15% of hazards at 76.67% accuracy with a
   38.24% false-positive rate.
   - **Why it matters for the talk:** the receipt as the
     unit of trust — the paper form of Grok's road back.
     A "done" the agent narrates is not a "done" the tool
     returned, and this system makes the difference
     checkable by a third party after the fact. Pair with
     Rei's fake-provider table: the receipt tells you
     what the provider accepted, and acceptance is all it
     tells you.
   - **Limits:** a single author, self-built conformance
     suites, 100% claims on its own tests; the live-trace
     numbers (76.67% accuracy, 38% false positives) are
     the honest ones, and they are far from clean.
