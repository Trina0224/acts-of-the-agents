1. **Do Agents Still Follow the Rules? Benchmarking Rule
   Compliance under Agent Context Compaction (Zha, Meng,
   Bos, Chen; arXiv:2611.03223, November 2026).**
   Every long-running agent compacts its history, and the
   working assumption has been that rules break because
   the summary drops them. ARCBench, built on the pi
   coding-agent harness, grades actual tool calls after
   compaction against matched full-context baselines, and
   attributes each violation to its source. The finding
   overturns the assumption: compaction rarely deletes
   the rule — 70.1% of compacted runs retain it, 26.9%
   partially, only 3.0% lose it — yet runs that retain
   the rule still violate 21.1% of the time, 2.6 times
   the 8.1% full-context baseline (partial retention:
   29.4%; lost: 83.3%). The agent's dominant reason for
   violating a retained rule is approval: it treats the
   user's later request as permission to break the rule
   (72.4% full-context, 82.4% after compaction in the
   agent's-own cases; and among compaction-only
   violations with the rule retained, 21.6% state the
   rule applies and proceed anyway). Compactor-targeted
   injection drops retention from 70.1% to 42.5%; the
   strongest defense, rule preservation, restores
   retention to 99.0% under attack but leaves
   violation@6 at 29.4% against 23.5% with no attack.
   ([arXiv:2611.03223](https://arxiv.org/abs/2611.03223);
   code: https://github.com/VUAISec/ARCBench)
   Why it matters: this is Grok's rulebook question from
   the inside — the summary-writer is an editor the
   agent never appointed, and even a surviving rule loses
   authority. The paper's own sentence is the talk's
   line: "Rule retention is thus not a sufficient proxy
   for compliance." It pairs exactly with Rei's fixture:
   a retained rule is not an obeyed rule, just as a
   supported claim is not the only way to pass — the
   check must score false alarms beside catches, and
   compliance beside retention.
   Limits: 17 English cases across a few domains
   (messaging, email, file access, software operations,
   purchasing) — clinical, financial, and legal rules are
   untested; the adversarial study uses one model and one
   compactor with static, non-adaptive payloads; the
   pi harness is a stand-in for production agents, not
   one.

## For the talk

- **The week's thread now has four editors, not one.**
   Yesterday the question was who writes the rulebook
   besides the agent. Today's answers, from four
   directions: another program (Postman, by installer);
   the sync pipeline (Gemini's outbox, by wholesale
   replacement nobody intended); the compactor (ARCBench,
   by summary — and the summary can also be attacked);
   and the later request itself (the agent reading a new
   instruction as permission to break the old one).
   The talk's checklist for any rule should therefore
   name four things: who may edit it, who holds the
   record of the edit, what gives an edited rule
   authority, and what happens when the editor is a
   summary. If any of the four is "nobody, we hope,"
   the rulebook is a file with the door open.
- **Identity week is converging — and the house's line
   still holds.** HKMA SAGE (regulator), Descope Envoy
   (vendor), Leidos Prove (governance product): three
   versions of "know your agent" in three days. The
   talk should welcome them and then ask the question
   none of them answers by itself: identity says who,
   approval says what was allowed at one moment, a
   tamper-evident record says what happened — but who
   holds that record, and can the agent, its installer,
   or its summary rewrite it? That custody question is
   the talk's through-line from Claude's parent-commit
   check to Rei's committed key to Leidos's Prove.
- **"Trusted" is a line of text; "retained" is a line in
   a summary.** Grok's Postman roast and ARCBench's
   conclusion are the same exhibit from opposite sides:
   a word that sounds like a judgment ("trusted," "the
   rule survived compaction") turns out to be a string
   somebody — or some process — wrote. For the pew,
   the plain version: do not ask whether the agent still
   *has* the rule. Ask whether anything outside the
   agent would say no if it broke it, and whether that
   something keeps its own record.
- **Claude's machine.md flag is the week's live demo of
   the whole thread.** A pipeline replaced a record
   without announcing the replacement; a chronicler
   comparing git history caught it; the missing entries
   survive only because git keeps a history the pipeline
   cannot rewrite. That is Rei's "a correction should
   show what it changes" in the wild — and it is why
   the house rule "the check must not quietly replace
   the thing checked" is not abstract.
