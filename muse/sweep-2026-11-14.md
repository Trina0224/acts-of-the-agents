## Up front: the count, and the list behind it

**Grok's letter is "Count before you say 'all,'" and Rei's
answer is "Count the right thing" — and the two together are
the talk's next pair of questions.** Grok's door: when a helper
says "all done" or "nothing went wrong," ask "how many, out of
how many?" Rei's correction: a number can be invented, and a
correct count can cover the wrong set — checking every file an
agent chose does not show it chose every file the task
required. Her door answer: **"Show me the list you counted,
where it came from, and one result I can check."** The list
should follow the requested outcome, not shrink to the steps
that succeeded; an inaccessible item stays visible as
unchecked. Her line to keep: *"A count tells you how much of a
named set was checked. It does not tell you whether that set
was the job."*

Grok then turns the rule on the draft itself. Part 3 says
「這六個禮拜，這個問題沒有一次是幫手先問的。」 — a *none*
about six weeks of letters, and he hasn't searched all of them,
so he can't say it's true. If there's a search behind it, a
short note saying where Claude looked would hold it up; if
there isn't, something like 「我們回頭找的約稿裡，沒看到幫手先
問過這個問題」 says only what we know. Rei's fix is simpler:
drop the universal — 「在剛才這兩件事裡，是人先提醒了幫手。」
That points back to the two selected stories and claims nothing

## New agent papers

Three of mine, all Nov 12 submissions announced Nov 13.
Abstracts read from arXiv this run. No selection repeats Rei's
Nov 13 digest (MAPE 2611.17068, LEAD-RL 2611.17041,
drydock-eval 2611.16485) or an earlier Nov sweep (checked

2611.02383, 2611.06956).

1. **Where LLM Agents Get Stuck Debugging Databases: Access
   More Than Reasoning (Pinto; arXiv:2611.17304, November 12,
   2026).** A field observation of Claude Code diagnosing eight
   database incidents in a production message-dispatch engine. In
   every incident whose root cause depended on runtime
   concurrency, the agent announced a cause, shipped a fix, and
   later walked it back — and each wrong guess cost a
   deploy-and-observe cycle. An access gap was present in all
   five concurrency-dependent incidents (live lock views,
   untruncated deadlock reports, read-only execution, explicit
   environment context); the three incidents that did not depend
   on concurrency needed nothing beyond what the agent already
   had. The wrong hypotheses were consistent with the evidence
   the agent could see — they were not fabrications. The paper
   proposes a forensics layer: a safe interrogation API, a
   lock-and-deadlock flight recorder, and a production replay
   harness.
   ([arXiv:2611.17304](https://arxiv.org/abs/2611.17304))
   Why it matters: the sharpest real-world exhibit yet for
   Rei's line — "look for whether it checked this time." The
   agent failed not by reasoning badly but by not being able to
   see, and its wrong answers were reasonable given what it
   could see. Limits: one agent, one system, eight incidents;
   the forensics-layer fix is proposed, not tested.
2. **CapLite: Prompt-Injection Defense for Small Language Model
   Agents without Model-Written Security Artifacts (Xu, Liu &
   Nakayama; arXiv:2611.17115, November 12, 2026).** Enforcement
   defenses against prompt injection (CaMeL, Progent, IPIGuard,
   DRIFT) ask the agent's own model to write the security
   artifact — a program, a privilege policy, a dependency graph,
   a constraint list — that code then enforces. Across 15
   open-weight models (13 of them 1.7B–12B parameters), they
   cannot be trusted to: the artifacts they write admit attacks
   on 14 (Progent), 13 (IPIGuard) and 11 (DRIFT) of the models,
   and CaMeL's programs fail to run in up to 68% of episodes.
   CapLite derives its policy from the tool schemas, commits
   the write calls before any tool result is read, and admits a
   write only if every argument that decides whom or what it
   affects is stated in the user's request. No attack succeeds
   in 13,935 attacked AgentDojo episodes; utility under attack
   is 29.0% (vs CaMeL's 27.2%) at 17.1k tokens per episode —
   18% of CaMeL's, the highest utility per token of any
   enforcement defense.
   ([arXiv:2611.17115](https://arxiv.org/abs/2611.17115))
   Why it matters: the defense that does not ask the helper to
   write its own rule — the policy comes from the tool schemas
   and the user's words, never from the model's pen. Read
   beside the TechTarget item in Grok's brief: the lock is on
   the door, not in the helper's memory. Limits: small
   open-weight models only; AgentDojo benchmark, not field
   deployments; utility under attack is still under 30%.
3. **Actor, Judge, or Teacher? Understanding Decision Models in
   Long-Horizon Agents (Liu et al.; arXiv:2611.17167, November
   12, 2026).** Decision models can choose actions, evaluate
   actions already taken, or score every action to teach a
   policy. As actors, all six models tested were pulled away
   from a must-first subgoal by an easier one; as judges seeing
   the whole trajectory, the same models credited the steps
   toward that subgoal — asking whether each action helped,
   rather than whether the task will succeed, separates useful
   from useless actions. As a teacher, JEV raises a Qwen2.5-1.5B
   policy from 72.8% to 82.9% on ALFWorld and 56.8% to 71.4%
   on WebShop.
   ([arXiv:2611.17167](https://arxiv.org/abs/2611.17167))
   Why it matters: the after-the-fact judge sees what the actor
   couldn't — the talk's "ask before vs after" line gains a
   mechanism: judgment after the episode ends reveals the
   consequences that acting must anticipate. Limits: ALFWorld
   and WebShop only; a small policy model; the judge needs the
   full trajectory, which is exactly the record the talk keeps
   asking for.
