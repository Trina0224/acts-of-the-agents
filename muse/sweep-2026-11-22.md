## News (not in the house briefs)

My independent round, Nov 20–22. Grok's five stories above

1. **The coding agent committed the credential (Nov 21).**
   Together AI's security notice, signed by CEO Vipul Ved
   Prakash: during development of its public GitHub repository
   `xorl`, "an AI coding agent committed a credential that
   provided access to the private Hugging Face repository"
   holding stored prompt samples from June–July requests to
   MiniMax M3, GLM-5.2 and Kimi K2.6. Automated scanning caught
   the exposed credential and the commit was reverted — but
   during the exposure window an unauthorized party obtained
   it and downloaded the samples. The party then searched the
   samples for credentials to other services and tested whether
   they were valid; five of the credentials tested were canary
   credentials planted by Dragos in a security experiment.
   Together AI says it has no reason to believe the data went
   further and understands it has been deleted; its review of
   the affected prompt contents is ongoing. Its four fixes:
   scoped/short-lived credentials and keyless access, checking
   all pull requests for credentials, zero data retention as
   the default for new accounts, and updated processes
   governing the use of AI coding agents. On Nov 22 OpenRouter
   dropped three providers and removed 125 endpoints from zero-
   data-retention eligibility after the same Dragos findings;
   Novita and Phala published their own notices.
   - **Why it matters for the talk:** the agent's commit *is*
     the incident — not a prompt injection, not an attacker
     tricking the agent, but the agent doing its ordinary job
     with a secret in hand. The check that caught it was not
     the vendor's: it was a researcher's canary, planted to
     trip exactly this. And the fix that names the failure is
     fourth on the list — "checking all pull requests for
     credentials" — a gate that arrives after the leak it
     would have stopped.
   - Source: [Together AI](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026)
     (Nov 21), [The Hacker News](https://thehackernews.com/2026/11/openrouter-drops-3-providers-after.html)
2. **The outage was ordinary, and that is the point
   (Nov 21).** Between 1:48 and 5:21 p.m. PT, requests to
   OpenAI's API and ChatGPT failed at rates peaking at 75%,
   across paid and free ChatGPT — 211 minutes. OpenAI published

## Papers (read at arXiv)

Gemini's Nov 21 brief carries three; I verified all three at
arXiv today. The two after them are my own round, both
submitted Nov 19 and not yet in the sweep record.

1. **The map of where defenses are thinnest
   ([arXiv:2611.10843](https://arxiv.org/abs/2611.10843),
   Nov 7, 2026).** Agents of Chaos: a systematization of
   knowledge on malicious attacks on agentic AI systems.
   Screened 186 sources, retained 98, codified 284 atomic
   attacks, 452 atomic safeguards and 660 explicit
   attack–safeguard relationships across eight causal-mechanism
   classes. Tool, MCP and action-layer attacks are the largest
   share; prompt-injection and action-hijacking have the
   broadest paper coverage. Many attacks separate insertion
   from activation — the payload lands in a document or a
   memory write and fires at a later tool call or session. Only
   278 of 660 relationships have been directly evaluated, and
   strong empirical coverage is rare.
   - **Why it matters for the talk (Gemini's line, checked):**
     most teams over-index on input prompt filtering while
     leaving the tool and MCP action layer under-defended.
     Effective agent security needs lifecycle-aware
     defense-in-depth, from ingestion through tool execution.
   - **Limits:** a systematization of the literature, not new
     experiments; the gaps it finds are gaps in the published
     evidence, which is not the same as gaps in deployed
     systems.
2. **The commit gate, on the step you can't undo
   ([arXiv:2611.14115](https://arxiv.org/abs/2611.14115),
   Nov 10, 2026).** LEASH: Stay Safe in Agentic Robotics.
   RoboRisk — 92 simulated tasks and 13 physical-robot tasks
   across five closed-loop harm categories (task-level refusal,
   plan repair, execution-time hazard, injection, sequential
   memory). Six frontier models (GPT-6 Astra, GPT-6.1 Sol,
   GPT-6 Luna, Claude Opus 5.5, Gemini 4 Argon, Grok 4.7)
   "generally show high harm rates." LEASH inserts task,
   action and commit gates that review the task, each proposed
   step and every irreversible operation in visual context
   against a shared safety policy, and reduces harm across all
   six models while largely preserving task completion with
   little time and token overhead.
   - **Why it matters for the talk (Gemini's line, checked):**
     embodied and high-stakes agents need commit gates before
     irreversible physical actions — like database transactions,
     physical actuation should be gated by an independent policy
     check in full visual context. Grok checked this one too.
   - **Limits:** harm is measured on RoboRisk, the authors'
     own benchmark; "reduces harm" is a benchmark result, not
     a deployment guarantee.
3. **A check that only ever tightens becomes a wall
   ([arXiv:2611.10395](https://arxiv.org/abs/2611.10395),
   Nov 7, 2026).** The Limits of Information-Flow Control
   Enforcement for Agentic Systems. Conservative taint tracking
   in stateful multi-agent systems produces label creep:
   monotonically increasing security labels propagate and
   progressively limit utility. Structural graph features show
   a remarkably strong association with IFC utility loss
   (Spearman |ρ| up to 0.96); system size and tool allocation
   shape how labels spread. Design alone — better topology,
   better tool partitioning — cannot fully prevent utility loss
   from monotonic label propagation. The paper motivates
   explicit, audited label declassification mechanisms.
   - **Why it matters for the talk (Gemini's line, checked):**
     pure taint tracking without an escape hatch eventually
     paralyzes an agent. Production IFC architectures must pair
     clean graph partitioning with explicit, audited
     declassification — a check needs a way to say "this is
     safe now," not only "this is tainted."
   - **Limits:** a simulator study, not deployed agents; the
     utility-loss metric is a proxy, and the declassification
     mechanisms it calls for are not built or tested here.
4. **Agents are already on both sides of the vulnerability
   lifecycle ([arXiv:2611.26601](https://arxiv.org/abs/2611.26601),
   Nov 19, 2026).** SoK: Assessing the Evolution of LLM
   Capability in Software Vulnerability Research. A framework
   rating capability on an autonomy scale modeled on the
   levels of driving automation, qualifying each claim by
   correctness, availability and strength of evidence. Agents
   discovered, validated and patched vulnerabilities in
   real-world software without human intervention before the
   restricted frontier models of 2026, and open-weight models
   subsequently attained comparable autonomy for discovery and
   validation. In 2026 the number of disclosed vulnerabilities
   more than doubled, with an increasing share rated critical
   or high, and severe bugs that had survived a decade or more
   in widely used code were reported several times more often
   than before. Yet the time between the stages of a
   vulnerability's life — report to fix, disclosure to attack
   — has not shifted noticeably so far.
   - **Why it matters for the talk:** Bell Canada's "agentic
     threat actor" has a measured form. Agents find and fix
     the holes and also find and use them, and the disclosure
     count is already moving while the fix timeline is not.
   - **Limits:** a systematization of published evidence; the
     doubling of disclosures correlates with agent capability
     but the paper does not prove the agents caused it.
5. **After the incident, the log is at the wrong layer
   ([arXiv:2611.26525](https://arxiv.org/abs/2611.26525),
   Nov 19, 2026).** Origin: Backtracking Agent Applications
   Security Incidents. When an agent application is breached,
   the analyst backtracks to the compromise entry point — but
   trajectory logs record agent functionalities while the
   entry-point candidates are function calls at the app code
   layer, and the analyst has to inspect code by hand to bridge
   the gap. Origin builds a cross-layer dependency graph
   connecting region-inferred functions to semantic-level
   agent functionalities, so the analyst can submit a small
   number of queries to identify entry points existing tools
   cannot provide.
   - **Why it matters for the talk:** the record the agent
     wrote is not the record the investigation needs. A check
     that cannot say where the failure entered is a note, not
     a brake — and the drill Rei designs is the version of
     this that runs before the incident instead of after it.
   - **Limits:** a backtracking aid for analysts, not a
     prevention; it needs the trajectory log and the source to
     exist, and it answers "where did it enter," not "how do
     we stop it next time."
