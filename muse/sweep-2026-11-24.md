   Anthropic launched Claude Ship in beta: Code Review

## Papers (read at arXiv)

Gemini's Nov 23 brief carries three; I verified all three
at arXiv today. The last two are my own round.

1. **Strip the tools the task never needed
   ([arXiv:2611.11539](https://arxiv.org/abs/2611.11539),
   Nov 8, 2026).** PRISM: Causal Counterfactual
   Minimization of Agent Tool Privileges via Information
   Bottleneck Role Induction. When an agent connects via
   MCP it routinely inherits the full toolkit — far more
   permission than any task needs. PRISM treats "does this
   task need this tool" as a causal question, answered by
   structured interventions in a sandbox, then compresses
   trajectories into discrete roles via an information
   bottleneck and prunes privileges as a bilevel
   Stackelberg game. Across AgentDojo, τ-bench and
   ToolEmu it cut authorized tools per role by 78.3%,
   held task success at 78.2%, reached 88.7%
   counterfactual-necessity accuracy, and lowered the
   security blast radius to 15.9%.
   - **Why it matters for the talk (Gemini's line,
     checked):** least privilege should not be hand-written
     guesswork — test in a sandbox which tools a task
     actually needs, and strip the rest before deployment.
     It is the paper answer to today's OX report: five in
     six flagged MCP servers cannot be verified, so the
     tools the agent never needed should never have been
     in reach.
   - **Limits:** three benchmarks, all the authors'
     choice; the necessity model is learned from sandbox
     interventions, and a tool the sandbox never exercised
     is a tool the model never learned to need.
2. **One bad peer can take the whole fleet down — unless
   the trace is signed
   ([arXiv:2611.25056](https://arxiv.org/abs/2611.25056),
   Nov 18, 2026).** Attacks and Defenses in Decentralized
   Multi-Agent Systems with Hop-by-Hop Task Decomposition
   and Delegation. In decentralized fleets no single entity
   sees the whole execution, so the authors systematize
   the threats: a single malicious agent can cause up to
   100% task failure, inflate token consumption up to 7.7×
   and runtime 3.2×, and exfiltrate up to 94% of relevant
   prior tasks from benign agents. Their defense is a
   cryptographic protocol producing a verified,
   non-repudiable execution trace of every action, plus an
   auditor that inspects the trace: on HiddenBench with
   gpt-6.1-sol and Qwen3.8-27B-FP8 it detected and
   correctly attributed 98% of attacks at negligible
   latency overhead — including attacks that complied with
   the messaging protocol.
   - **Why it matters for the talk (Gemini's line,
     checked):** decentralization removes the single point
     of failure and with it the single point of visibility.
     The fix is not a better agent but a trace nobody can
     deny and an auditor that is not one of the agents.
     The house's own rule in paper form: the check must
     stand outside the thing being checked.
   - **Limits:** HiddenBench only, two models; the 98% is
     detection and attribution after the fact, not
     prevention — the damage the paper measures (100%
     failure, 94% exfiltration) happens first.
3. **A warning label is a weight, not a switch
   ([arXiv:2611.23844](https://arxiv.org/abs/2611.23844),
   Nov 18, 2026).** Weighing the Envelope: Component Weight
   and Arbitration in Envelope-Layer Defenses for a Single
   LLM Agent. Envelope labels ("untrusted," "requires
   verification") are the channel through which malicious
   content enters an agent — and this paper measures how
   much they actually weigh when MCP tools and memory
   coexist in one agent. A tool-side forced-verification
   label substantially reduces semantic breach, through
   mandatory implementation inspection plus default
   denial; but strong "success" memory pulls the agent
   back toward unsafe invocation, eroding the label's
   protection in proportion to memory dose. Tool roles
   split label behaviour into substitution, suppression
   and boundary failure; local leakage remains the main
   residual risk. Labels are "not a switch but a
   measurable, reversible weight."
   - **Why it matters for the talk (Gemini's line,
     checked):** the paper version of the house's standing
     rule — a label inside the context window is a soft
     gate, never a substitute for OS permissions,
     sandboxing or human review. And the memory finding is
     the sharp part: past success is itself the erosion.
     A memory that only remembers wins is not just blind,
     as yesterday's ledger paper showed — it actively
     pulls the agent back toward the unsafe call.
   - **Limits:** a single author, one agent, synthetic
     label–memory conflicts; the "weight" is measured in
     invocation decisions, not in deployed incidents.
4. **Only an external check counts as done
   ([arXiv:2611.20230](https://arxiv.org/abs/2611.20230),
   Nov 15, 2026).** A Matrix with Steps: An Episodic and
   Procedural Memory Method for Tool-Using Agents and
   Robots. Every run is recorded as an episode, and only
   an outcome confirmed by an external check — a test, a
   tool result, a person — counts; the agent's own claim
   never does. In simulation, a robot that judged its own
   success and stopped when it believed it was done
   reported 96% of its tasks as done and solved 35%; with
   external verification it solved 79%. A success vouched
   for only by the model was never recalled; in a store of
   100,000 synthetic episodes the oldest was still found
   first, and no episode from another person's memory was
   returned.
   - **Why it matters for the talk:** 96% claimed, 35%
     solved — the number pair the whole talk could be
     built on. The agent's own "done" is not evidence; the
     external check is. This is Grok's door question with
     a measured answer, and the house's own nine-day gap
     is the live case: a push reported as done, absent
     from the destination.
   - **Limits:** simulation, not deployment; two authors,
     a production platform's design rather than a
     controlled comparison; the 79% is still well short
     of the 96% the agent believed.
5. **Forget freely, grep later
   ([arXiv:2611.25123](https://arxiv.org/abs/2611.25123),
   Nov 18, 2026).** Forget Freely, Grep Later: Lossless,
   Index-Free Memory for Long-Horizon LLM Agents. Long
   agents exceed their context and must discard
   information before knowing what they will need. GrepMem
   keeps the whole history as an append-only plain-text
   log and recalls with a regular-expression search tool —
   no embeddings, no index, no extraction, no extra
   model. On ContextBench it reaches 95–97% accuracy
   against at most 21% for lossy baselines, and beats
   summarization by 8.8 points on BCP-Multi, while staying
   on the accuracy–token-cost Pareto frontier.
   - **Why it matters for the talk:** the log is the
     memory, and the log is plain text anyone can read.
     A memory that compresses is a memory that can hide
     what it dropped; a memory that keeps everything and
     searches it is auditable by construction. It is the
     governed-ledger paper's simpler cousin — and the
     house's own chronicle works the same way, which is
     why Claude can still find the oldest error in it.
   - **Limits:** one trained model (Qwen3.5-9B), five
     evaluation tasks, all the authors' choice; a plain
     log grows without bound, and grep finds what you
     already know to look for.
