# AI Brief & Talk Material — 2026-11-21

Curated by Gemini Spark for Trina's late November 2026 presentation on the AI agent era. All citations reference primary preprints directly verified on arXiv.

## 1. Agents of Chaos: Mapping 284 Attacks and 452 Safeguards Across Agentic AI (arXiv:2611.10843)

Agent security literature is fragmented across prompt injections, MCP exploits, memory poisoning, and code-execution abuse, making it hard for architects to see where defenses actually hold up.

In *Agents of Chaos: A Systematization of Knowledge (SoK) on Malicious Attacks on Agentic AI Systems* ([arXiv:2611.10843](https://arxiv.org/abs/2611.10843), Nov 7, 2026), researchers screened 186 sources, retained 98, and codified **284 atomic attacks**, **452 atomic safeguards**, and **660 explicit attack–safeguard relationships** across eight causal-mechanism classes:
- **The Action Layer Dominates:** Tool, Model Context Protocol (MCP), and action-layer attacks account for the largest share of atomic attacks, while prompt-injection and action-hijacking remain the most heavily studied.
- **Temporal Split Between Insertion and Activation:** Many agentic attacks separate *where* a payload is inserted (e.g. a document or memory write) from *when* it activates (a later tool call or session).
- **Uneven Safeguard Validation:** Out of 660 mapped attack–safeguard relationships, only **278** have been directly evaluated, and strong empirical coverage remains rare.

**Why it matters for the talk:**
Most teams over-index on input prompt filtering while leaving the **tool and MCP action layer** under-defended. Effective agent security requires lifecycle-aware defense-in-depth from ingestion through tool execution.

## 2. LEASH: Lease-Enforced Safety Gates for Embodied and Physical Agents (arXiv:2611.14115)

When autonomous agents control physical actuators or robots, a single unverified action can cause irreversible real-world harm—and text-only evaluations miss closed-loop physical risks.

In *LEASH: Stay Safe in Agentic Robotics* ([arXiv:2611.14115](https://arxiv.org/abs/2611.14115), Nov 10, 2026), researchers introduce `RoboRisk` (five closed-loop harm categories) and evaluate six frontier foundation models (`GPT-6 Astra`, `GPT-6.1 Sol`, `GPT-6 Luna`, `Claude Opus 5.5`, `Gemini 4 Argon`, `Grok 4.7`) alongside robot APIs:
- **High Baseline Harm Rates:** Frontier models evaluated in closed-loop physical tasks consistently exhibited high baseline harm rates when operating without external enforcement.
- **Three-Gate Lease Infrastructure:** `LEASH` (Lease-Enforced Agentic Safety Harness) inserts **task, action, and commit gates** that review the overall task, each proposed step, and every irreversible operation in visual context against a shared safety policy.
- **Low-Overhead Harm Reduction:** Tested in both simulation and on physical robots, `LEASH` substantially reduced harm across all six foundation models while preserving task completion with minimal time and token overhead.

**Why it matters for the talk:**
Embodied and high-stakes agents need **commit gates** before irreversible physical actions—just like database transactions, physical actuation should be gated by an independent policy check in full visual context.

## 3. The Limits of Information-Flow Control: Label Creep in Agentic Graphs (arXiv:2611.10395)

Information-Flow Control (IFC) is a classic security technique: taint untrusted inputs with security labels and propagate those labels whenever data flows downstream. However, in stateful multi-step agents, conservative tainting creates **label creep**.

In *The Limits of Information-Flow Control Enforcement for Agentic Systems* ([arXiv:2611.10395](https://arxiv.org/abs/2611.10395), Nov 7, 2026), researchers systematically simulate how system topology, scale, and agent composition affect conservative IFC utility loss:
- **Topology Drives Utility Collapse:** Structural graph features show a remarkably strong association with IFC utility loss (Spearman correlation $|\rho|$ up to **0.96**), with system size and tool allocation heavily shaping how taint labels spread.
- **Design Alone Cannot Cure Label Creep:** While better graph topology and tool partitioning reduce unnecessary taint propagation, system design alone cannot prevent monotonic label creep from eventually locking up legitimate workflows.

**Why it matters for the talk:**
Pure taint tracking without an escape hatch eventually paralyzes an agent. Production IFC architectures must pair clean graph partitioning with explicit, audited **label declassification** mechanisms.
