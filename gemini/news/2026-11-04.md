## 1. The Three Layers of Autonomous Agent Containment

To deploy AI agents safely in enterprise and personal workflows, organizations cannot rely on conversational alignment alone. Long-term reliability requires three concentric physical and architectural layers:

1. **The Virtualization Layer (Application Kernels & MicroVMs)**:
   - Untrusted code, web agents, and LLM tool executions must be confined within user-space kernels (such as Google's gVisor `runsc`) or microVMs (such as Firecracker).
   - This physical sandbox traps system calls, caps memory allocation (5.0 GiB), and prevents container escape even in the event of arbitrary code execution.
2. **The Policy Layer (Standing Contractual Mandates)**:
   - Prompting human users for permission on every granular file read or tool call induces severe approval fatigue, leading humans to approve actions reflexively.
   - Robust governance relies on pre-authorized, machine-readable operational envelopes: explicit directory allowlists, strict tool schemas, and hard perimeter fences.
3. **The Mutation Layer (Decoupled Pipelines)**:
   - Generative reasoning must be separated from external mutation authority.
   - An agent writes to an isolated outbox; a dedicated, deterministic CI/CD pipeline (such as GitHub Actions) validates checksums and executes production changes.

**Takeaway for the Talk**: Trust in autonomous AI is not an emotional feeling; it is a three-layer defense in depth that makes unauthorized damage physically impossible.

## 2. Destination-First Recovery: Solving the Missing Receipt Problem

In distributed agent architectures, the most common operational hazard is handling network timeouts and ambiguous errors:

- **The Naive Hazard**: When a tool invocation drops connection or times out, the model assumes failure and re-executes the tool call. For non-idempotent actions (booking a seat, transferring money, dispatching an email), this causes silent, costly duplicate actions.
- **The Destination-First Protocol**:
  1. *Timeout as Uncertainty*: A timeout or network drop is recorded strictly as unconfirmed state, never as a guaranteed failure.
  2. *Destination Inspection*: The agent queries the destination system (checking order status, mailbox outbox, or git commit tree) before taking any further action.
  3. *Halt on Ambiguity*: If destination state cannot be verified, the agent halts and prompts rather than attempting a speculative retry.

**Takeaway for the Talk**: In autonomous systems, recovery begins at the destination, not at the retry button.

## 3. Auditable History vs. Conversational Drift

Over multi-week horizons, large language models suffer from context dilution, conversational rationalization, and memory drift:

- Relying on conversational recall to determine what happened in prior weeks leads to compounding factual errors.
- True accountability requires an external, append-only system of record: diffable Git commit histories and immutable machine logs.

**Takeaway for the Talk**: Never ask an agent to remember what it did last month. Inspect the commit history that was written when the action occurred.
