## 1. AgentPRO: Compiler Optimizations for Live Agent Workflows (arXiv:2611.00628)

Agent workflows routinely waste tokens and latency on redundant file reads, fragmented generation calls, and static plans that ignore runtime state.

In *AgentPRO: Coordinating Compiler Optimizations for LLM Agent Workflows* ([arXiv:2611.00628](https://arxiv.org/abs/2611.00628), Oct 31, 2026), researchers apply classic compiler optimization passes directly to agentic execution:
- **Hierarchical Dependency IR:** `AgentPRO` separates planned duties, generation regions, and concrete tool operations—explicitly distinguishing *execution dependencies* from *observation dependencies* required for generation.
- **Cross-Scope Transformations + Runtime Guards:** Region passes merge compatible duties into fewer LLM calls, while operation passes eliminate redundant reads (which in turn unlocks further region merging). Every transformation is protected by runtime guards with safe fallback paths.
- **41.85% Fewer Tokens on AppWorld:** Across 115 tasks with guarded workflow transformations, `AgentPRO` cut all-attempt mean token consumption by **41.85%** and mean component time by **6.61%**, completing **110 of 115 tasks**.

**Why it matters for the talk:**
Agent orchestration is ready for compiler engineering. Separating execution order from data-observation dependencies lets a runtime fuse calls and prune redundant reads automatically—with deterministic guards ensuring safe fallback if assumptions break.

## 2. StateGraph: Counterfactual Dependency Tracking for Long-Term Memory (arXiv:2611.02912)

When a fact changes in a long-running workspace—a deadline moves, an API key rotates, or a file is deleted—standard vector-store memories only update that single record, leaving stale derived beliefs intact.

In *A State Change Is Local, Its Consequences Are Not: Dependency-Aware State Revision for Long-Term Agent Memory* ([arXiv:2611.02912](https://arxiv.org/abs/2611.02912), Nov 2, 2026), researchers introduce `StateGraph`:
- **Counterfactual Edge Verification:** `StateGraph` recovers a dependency graph from interaction histories and tests each edge counterfactually (*"would this dependent state still hold if its premise were lost?"*), separating true support dependence from mere semantic similarity.
- **Cascading Invalidation:** When a premise changes, `StateGraph` invalidates dependent states only when a strict dependency breaks and no independent support path survives.
- **+26.0 pp Margin at Depth 3+:** On `StateChangeBench` (50 cases with multi-hop cascades and action consequences), `StateGraph` beat `CUPMem` by **6.9 percentage points Impact-F1 at depth 1** and **26.0 percentage points at depth 3+**.

**Why it matters for the talk:**
In stateful systems, a local edit has non-local consequences. Long-term agent memory needs **dependency graphs**, not flat vector retrieval, so updating one fact cleanly invalidates every stale conclusion built on top of it.

## 3. MixUA: Scoped Memory Sharing Without Cross-User Leaks (arXiv:2611.10439)

Self-evolving agents improve by distilling past trajectories into reusable lessons. However, in multi-user, multi-agent organizations, sharing those lessons globally risks leaking one user's private preferences or sensitive context to another.

In *Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction* ([arXiv:2611.10439](https://arxiv.org/abs/2611.10439), Nov 7, 2026), researchers propose `MixUA` alongside `CrossLearnBench`:
- **Four-Tier Memory Scoping:** `MixUA` distills trajectories into lessons and routes each lesson to one of four scopes—`user-agent pair`, `user`, `agent`, or `global`—based on who benefits and what may be disclosed.
- **Higher Utility with 0.02% Leakage:** Across 5 users and 7 agents on `CrossLearnBench`, `MixUA` boosted pass rates by up to **16 points over no memory** and **5 points over a single global memory**, retained up to **90%** of stated user preferences, and leaked a planted private fact in at most **0.02%** of privacy probes.

**Why it matters for the talk:**
Shared agent learning cannot live in a single global bucket. Multi-tenant agent platforms must enforce **multi-granularity memory scoping** so general workflow lessons travel freely while user-specific context stays strictly isolated.
