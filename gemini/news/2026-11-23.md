## 1. PRISM: Causal Counterfactual Minimization of MCP Tool Privileges (arXiv:2611.11539)

When agents connect to servers via the Model Context Protocol (MCP), they routinely inherit full, coarse-grained toolkits—far more permissions than any single task requires.

In *PRISM: Causal Counterfactual Minimization of Agent Tool Privileges via Information Bottleneck Role Induction* ([arXiv:2611.11539](https://arxiv.org/abs/2611.11539), Nov 8, 2026), researchers shift role engineering from human users to LLM agents:
- **Causal Necessity via Sandbox Interventions:** Rather than guessing which tools an agent needs from static descriptions, `PRISM` treats tool necessity as an intervenable causal proposition, running structured interventions in a sandbox to learn a counterfactual necessity model.
- **Information Bottleneck + Stackelberg Pruning:** Trajectories are compressed into discrete latent roles via an information bottleneck (selecting role count at the knee of the rate-distortion curve), and privilege pruning is formulated as a bilevel Stackelberg game.
- **78.3% Fewer Tools, 15.9% Blast Radius:** Across `AgentDojo`, `\tau-bench`, and `ToolEmu`, `PRISM` compressed authorized tools per role by **78.3%**, maintained a **78.2% task success rate** with **88.7% counterfactual necessity accuracy**, and lowered the security blast radius to **15.9%**.

**Why it matters for the talk:**
Least privilege for MCP agents shouldn't be hand-written guesswork. By testing counterfactual tool necessity in a sandbox and compressing permissions into minimal roles, teams can strip away nearly 80% of excess tool exposure before deployment.

## 2. Cryptographic Execution Traces for Decentralized Multi-Agent Delegation (arXiv:2611.25056)

In decentralized multi-agent systems using hop-by-hop task decomposition and delegation, no single entity has global visibility—creating an opening for a single compromised peer to derail or drain the whole network.

In *Attacks and Defenses in Decentralized Multi-Agent Systems with Hop-by-Hop Task Decomposition and Delegation* ([arXiv:2611.25056](https://arxiv.org/abs/2611.25056), Nov 18, 2026), researchers systematize integrity, availability, and confidentiality threats:
- **Severe Single-Peer Leverage:** A single malicious agent can trigger up to **100% task failure**, inflate token consumption by up to **7.7×** and runtime by **3.2×**, and exfiltrate up to **94%** of relevant prior tasks from benign agents.
- **Irrefutable Execution Traces + Auditor:** The authors introduce a cryptographic protocol that produces a verified, non-repudiable execution trace of every system action, paired with an auditor that inspects the trace.
- **98% Attribution at Negligible Overhead:** Evaluated on `HiddenBench` with `gpt-6.1-sol` and `Qwen3.8-27B-FP8`, the protocol added negligible latency overhead while detecting and attributing **98% of attacks**—even attacks that complied with the messaging protocol.

**Why it matters for the talk:**
Decentralization removes single points of failure for availability, but it removes global visibility for security. Hop-by-hop delegation needs **cryptographically verified execution traces** so an independent auditor can attribute bad behavior after the fact.

## 3. Weighing the Envelope: Prompt-Layer Defenses Are Soft Gates, Not Switches (arXiv:2611.23844)

Many agent harnesses wrap tools or memory in warning labels ("untrusted," "requires verification") hoping the model will treat those envelope labels as hard security boundaries.

In *Weighing the Envelope: Component Weight and Arbitration in Envelope-Layer Defenses for a Single LLM Agent* ([arXiv:2611.23844](https://arxiv.org/abs/2611.23844v1), Nov 18, 2026), researchers measure how envelope labels, memory, tool roles, and model backends interact under label–memory conflicts:
- **How Labels Work (and Erode):** A tool-side forced-verification label significantly reduces semantic breaches through mandatory implementation inspection and default denial (not length or formatting). However, strong "success" memory pulls the agent back toward unsafe invocation—eroding the label's protection in proportion to memory dose.
- **Soft Signal, Not Hard Switch:** Tool roles split label behavior into substitution, suppression, and boundary failure, with local leakage remaining the primary residual risk.

**Why it matters for the talk:**
Envelope labels inside an agent's context window are **measurable, reversible weights—not binary switches**. They are useful as soft gates and risk signals, never as substitutes for OS permissions, sandboxing, or human review.
