## 1. Connector Fault Tolerance: Decoupling the Outbox from the Synchronizer

In production agentic systems, external tool integrations (such as Model Context Protocol servers or third-party OAuth connectors) are inherently less stable than core runtime primitives. A connector may fail to mount due to transient platform routing, token refresh boundaries, or session initialization races—even when explicitly invoked by the user.

- **The Monolithic Failure Mode**: When an agent is responsible for both *generating* an artifact and *pushing* it directly to an external system of record (like a Git repository), a missing connector halts the entire workflow or traps work inside an ephemeral container.
- **The Decoupled Outbox Pattern**: By routing agent outputs to a high-availability staging layer (such as a mounted Google Drive sync folder) and delegating repository mutation to an independent, scheduled CI/CD workflow (GitHub Actions), the system achieves connector fault tolerance.
- **Takeaway for the Late November Talk**: Don't build agent workflows where a single dropped tool binding loses the day's work. Separate the *outbox* (where the agent deposits plain-text work) from the *synchronizer* (which commits to the canonical shelf).

## 2. Preventing Context Pollution Under Partial Blindness

In asynchronous multi-agent environments where agents read and write to a shared repository, partial outages create an epistemic hazard: an agent might lose read access to its peers' latest updates while retaining write access to its own outbox.

- **The Smoothing Hazard**: Large language models are trained to maintain conversational coherence. Without strict constraints, an agent lacking read access may subtly infer, generalize, or guess what teammates likely wrote, introducing unverified claims into the shared record.
- **Explicit Blindness Declarations**: A reliable architecture treats read failures as first-class state. When a read tool is unmounted, the agent must log the exact boundary ("GitHub MCP unmounted at 2026-10-24 23:09 PT; peer commits from 10/23–10/24 uninspected") and restrict its output to locally verifiable state and self-contained analysis.
- **Takeaway for the Late November Talk**: Honesty about what an agent *cannot see right now* is just as critical as accuracy about what it can see. Explicit read-blindness logs prevent one agent's connector glitch from polluting the group's shared memory.
