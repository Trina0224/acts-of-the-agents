# AI Brief & Talk Material — 2026-10-13

Curated by Gemini Spark for Trina's late November 2026 church presentation on the AI agent era. All papers below are drawn from arXiv's October 12 announcement list and verified directly against primary preprint sources.

## 1. LongHarness: Revisable Evidence Beats an Ever-Growing Notebook (arXiv:2610.13075v1)

A common assumption in agent architecture is that accumulating more interaction history improves performance. In practice, append-only memory structures accumulate contradictory observations and uncorrected assumptions.

In *LongHarness: Revisable Evidence Beats an Ever-Growing Notebook* ([arXiv:2610.13075v1](https://arxiv.org/abs/2610.13075v1), announced Oct 12, 2026), researchers evaluate structured evidence management across long-horizon QA benchmarks. LongHarness explicitly separates source-linked empirical observations from synthesized conclusions, and implements explicit *retirement* operations when newer observations contradict older records. On OfficeQA Pro V2 using GLM-5.3-Flash:
- **Append-only evidence accumulation** scored **51.1% exact match**.
- **Generic editable working notes** scored **53.3%**.
- **LongHarness (with active evidence retirement)** scored **61.1%** (+18.9 percentage points over baseline).

**Why it matters for the talk:**
Trustworthy memory is not an ever-growing diary. For an agent to remain reliable over weeks, its architecture must include explicit mechanisms to deprecate, correct, and retire outdated evidence when reality contradicts it.

## 2. Humanize MLE Agents: Resetting Context While Preserving Work (arXiv:2610.13494v1)

When an agent works on a complex multi-hour task, keeping a single conversational context active leads to prompt bloat, attention degradation, and hallucination propagation.

In *Humanize MLE Agents: Reset Context While Preserving Useful Work* ([arXiv:2610.13494v1](https://arxiv.org/abs/2610.13494v1), announced Oct 12, 2026), researchers demonstrate that long-running tasks are better handled by alternating agents and deliberately resetting conversational context after at most five experimental iterations. Validated code artifacts and performance checkpoints survive the handoff, while conversational scratchpads are cleared.
- Across 75 MLE-bench competitive tasks over three repeats with six hours allocated per run, the alternating reset framework achieved **78.2% any-medal performance**, versus **72.4%** for the matched single-agent baseline.

**Why it matters for the talk:**
Long-horizon autonomy does not require an infinite context window. The safest operational pattern separates the **durable artifact** (which persists on the filesystem) from the **reasoning context** (which is periodically wiped clean to eliminate bias).

## 3. RATED: Choosing Tools by Operational Health, Not Semantic Relevance Alone (arXiv:2610.13889v1)

Most tool-using agents select APIs using semantic similarity: matching the user's intent to the tool's textual description. When an external service experiences downtime or auth failure, semantic matching repeatedly calls the broken endpoint.

In *RATED: Choose Tools Using Reliability as Well as Relevance* ([arXiv:2610.13889v1](https://arxiv.org/abs/2610.13889v1), CIKM 2026), researchers combine a frozen semantic encoder with a discounted contextual bandit that updates tool selection weights based on live execution feedback.
- In environments where persistent outages affected 30% of tools, standard semantic selection produced **19.4% failed-tool calls**, whereas RATED reduced failure selection to **2.9%** while achieving an **82.1% post-failure task completion rate** (outperforming simple hard blacklisting at 80.2%).

**Why it matters for the talk:**
An agent cannot rely purely on prompt-level assumptions about what tools are supposed to do. Operational trustworthiness requires real-time health feedback—detecting when a tool fails and adapting the plan rather than persistently pounding on an unavailable door.
