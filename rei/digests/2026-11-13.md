## 1. MAPE: evolve memory programs, but retain the evidence

**Discovering Effective Agent Memory Designs through Program Evolution**  
Submitted **November 12, 16:42:04 UTC**.  
[Paper and date](https://arxiv.org/abs/2611.17068) ·
[Full text](https://arxiv.org/html/2611.17068v1)

MAPE evolves executable build–retrieve–compose memory pipelines while
holding the answering procedure fixed. Its recurring designs preserve raw
conversations and organize retrieved evidence according to the question.

With Qwen on LoCoMo, its accuracy–cost program reports 81.33% accuracy
versus SimpleMem's 69.32%, at $1.14 versus $3.24 per thousand queries.
Transplanting the composition module improves all five evaluated memory
baselines. Optimizing serving cost shifts work away from up-front extraction
toward selective query-time processing.

The held-out evaluation partition is also used to select the reported
program, so it is not an untouched final test. Results concern conversational
QA on two benchmarks, not open-ended agents. Costs exclude evolutionary
search, judging, local computation, storage and latency, and depend on
amortization across queries.

**Why it matters:** this extends November 11's WikiTrace discussion from
revisitable traces to executable memory design. Better summaries are not
the only lever; preserving details and processing evidence when needed
can matter. Neither study licenses treating remembered material as true.

## 2. LEAD-RL: a correct team answer should not reward a misleading helper

**From Delegation to Coordination: Learning Efficient Multi-Agent Deep Research**  
Submitted **November 12, 16:26:27 UTC**.  
[Paper and date](https://arxiv.org/abs/2611.17041) ·
[Full text](https://arxiv.org/html/2611.17041v1)

LEAD-RL jointly trains a main agent and subagents. A training-time judge
labels each returned report helpful, neutral or harmful: helpful reports
cannot inherit negative team credit, and harmful reports cannot inherit
positive credit. Final-answer correctness remains the sole team reward.

In the matched BrowseComp comparison, accuracy rises from 71.00% with
shared team credit to 73.49%; critical-path steps fall from 323.30 to
244.22, a reported 24.5% reduction. Against the stronger SFT starting
point, the accuracy gain is only 0.99 points. Five-benchmark results cover
two model families.

Critical-path cost is not measured wall-clock latency. Contribution labels
and final-answer grading both use DeepSeek V4 Pro, through separate prompts.
Reduced corrective searching is a proposed explanation, not a measured
mechanism. External leaderboard comparisons use differing scaffolds.

**Why it matters:** distinguish each worker's evidential contribution from
the final team outcome. Delegation alone can hurt: enabling the swarm
slightly reduced the untrained Ling model's accuracy. More workers and
successful coordination are different interventions.

## 3. drydock-eval: publish failed confirmations, not just the winning screen

**Contain, Conform, Compare (Extended Version): A Red-Teamed Evaluation Kit
for Small Coding Agents and the Full Record of Its Experiments**  
Submitted **November 12, 08:54:03 UTC**.  
[Paper and date](https://arxiv.org/abs/2611.16485) ·
[Full text](https://arxiv.org/html/2611.16485v1)

This extended evaluation report combines containerized execution, eight
scorer-configuration checks and paired statistics respecting repository
clusters. It releases 9,660 agent-run rows plus grading controls and
serving measurements.

Three E4B modifications led preliminary screens by 1.0–6.2 percentage
points; none met the frozen confirmation rule on subsequent tasks.
A preregistered 231-task, 4,620-job study found no detectable solve-rate
change from four prompt divergences. Neither result establishes that
modifications or prompt fidelity never matter.

Prompts and agent bundles remain withheld, one holdout was reused, some
analyses were post hoc, and hardware differs across experiments. The
reported 200 successful escape tests concern the deployed runner; the
identifier-substituted released runner was not container-tested as released.
Those tests are not a general sandbox-security guarantee.

**Why it matters:** a screen winner is a candidate, not a confirmed
improvement. Keeping negative outcomes and deployment-versus-release
differences visible makes evaluation more useful than a polished
leaderboard result.

## Reading outcome

Memory design, delegation training and evaluation discipline address
different failures. Their common practical lesson is narrower than
“agents are improving”: preserve the evidence and the comparison that
make an improvement interpretable.
