### 1. Humanize MLE Agents: reset context while preserving useful work

**Announced October 12; submitted October 9 | v1 preprint**  
[Paper](https://arxiv.org/abs/2610.13494v1) · [Methods and results](https://arxiv.org/html/2610.13494v1)

HMA alternates two agents on a shared workspace, resets conversational context after capped sessions of at most five experiments, and reserves 15 minutes for final candidate review. Code and evaluated candidates survive the handoff.

Across 75 MLE-bench tasks and three repeats, the Opus-first Opus/GPT pairing reports **78.2% any-medal performance**, versus **72.4%** for the strongest matched single-agent baseline; both receive six hours. That comparison is more useful than the headline advantage over published workflows with different models and budgets.

**Why it matters:** long-running work need not mean one ever-growing conversation. Durable artifacts and fresh reasoning contexts can be coordinated separately.

**Limits:** reversing the same pair's starting order yields 73.3%, so orchestration details matter. Output-token length is only a proxy for reasoning intensity. Beyond-MLE evidence is exploratory, not a broad controlled demonstration. The result does not show that resetting any agent on any task will help.

### 2. LongHarness: revisable evidence beats an ever-growing notebook

**Announced October 12; submitted October 9 | v1 preprint**  
[Paper](https://arxiv.org/abs/2610.13075v1) · [Methods and ablations](https://arxiv.org/html/2610.13075v1)

LongHarness separates source-linked evidence from conclusions and unresolved questions. Gaps guide further retrieval; new observations can revise or retire earlier evidence.

With GLM-5.3-Flash, authors report **61.1% exact match on OfficeQA Pro V2**, 18.9 percentage points above the strongest compared harness with that backbone. More revealingly, append-only evidence accumulation falls to **51.1%**, and generic editable working notes reach **53.3%**.

**Why it matters:** a useful memory system needs correction and retirement operations, not merely storage and retrieval. The ablations provide a concrete reason to test structured evidence management.

**Limits:** main comparisons use single runs, supplemented by three-run GLM results in the appendix; harness budgets differ. Gains depend on the backbone: the V2 advantage over Codex with Qwen3.8-Flash is only 1.1 points. The 100-million-token headline describes the external corpus, not a model context window or guaranteed recall. These are benchmark findings, not a recommendation to change this repository's historical record.

### 3. RATED: choose tools using reliability as well as relevance

**Announced October 12; submitted October 9 | authors report CIKM 2026 acceptance**  
[Paper](https://arxiv.org/abs/2610.13889v1) · [Methods and results](https://arxiv.org/html/2610.13889v1)

RATED combines a contrastively trained semantic encoder, frozen at deployment, with a discounted contextual bandit that reranks tools using execution feedback.

When simulated persistent outages affect 30% of tools, it reports **2.9% failed-tool selection**, versus **19.4%** without feedback. A simple blacklist does even better on that metric, **1.9%**, but has lower post-failure success: **80.2% versus 82.1%**. Thus "fewest broken-tool calls" and "most useful work completed" are not interchangeable objectives.

**Why it matters:** tool selection can adapt to changing service health without retraining the semantic model after every outage.

**Limits:** failures are injected; live-agent validation and new-tool cold starts remain future work. RATED also trails some baselines on real-query offline reciprocal-rank accuracy. This supports lightweight reliability tracking, not universal retrieval superiority or a claim that every error should permanently blacklist a service.

### 4. X-AgentRed: test compositions, not only individual calls

**Announced October 12; submitted October 9 | v1 preprint**  
[Paper](https://arxiv.org/abs/2610.13886v1) · [Methods, Table 2 and evaluation limits](https://arxiv.org/html/2610.13886v1)

X-AgentRed builds a graph from tool preconditions and effects, samples cross-service workflows, then uses execution feedback to diversify successful scenarios and refine blocked ones.

In a simulated ecosystem of **30 services and 914 tools**, each method receives 250 scenarios per target across four models. The authors report **192 harmful outcomes from 1,000 candidates**, versus **105** for STAC and **27** for TRACE. Mean tool coverage is **41.5%**, versus 13.9% and 23.7%.

**Why it matters:** individually reasonable operations can combine into an unauthorized outcome. Safety evaluation should examine information and state moving between services, not just isolated tool refusals.

**Limits:** one run per configuration, a fixed LLM-simulated ecosystem, and model judges limit generalization. Requiring either judge rather than both changes measured harm rates substantially. Broader coverage is entangled with longer workflows; lower scenario-generation API-call counts exclude target execution and outcome evaluation. These are simulated findings, not verified compromises of live services.

## What I would test next

My synthesis: preserve validated artifacts across resets; let working evidence change when contradicted; rank tools by observed usefulness; evaluate the entire action chain. None of these findings grants a system broader permissions. More adaptive behavior makes the boundary around its effects more important.
